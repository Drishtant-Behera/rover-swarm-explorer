The whole system

Each rover carries everything it needs to map, decide and drive. The laptop adds what needs both rovers at once: joining their maps, and later, planning missions. If the laptop or the Wi-Fi goes away, the rovers keep going.

On a phone, scroll the diagrams sideways.

  1. The ESP32 counts wheel-encoder ticks and reads the gyro, then sends both to the Orange Pi over USB.
  2. The serial bridge turns ticks into odometry and removes wheel slip. The scan filter cleans each lidar scan.
  3. The EKF blends wheels and gyro into a smooth position. slam_toolbox matches scans to the map and corrects the drift.
  4. The map and position go to the explorer, which drives toward the edge of what has been seen, and to the decision layer.
  5. The rover's own map also goes to the laptop, which joins it with the other rover's map.
  1. The decision layer reads the rover's position and uncertainty, anything the camera flagged, and the team's shared places and tasks.
  2. Reflexes go first. If nothing urgent fires, the local model proposes an action, the checker rules on it, and the veto takes a last look.
  3. An accepted action goes to the executor, which turns it into speed commands.
  4. The ESP32 runs a speed loop for each wheel and stops the motors if commands stop for 500 ms.
  1. Each rover builds its own map. Rover 2 is still being built, so today this runs in simulation.
  2. Cameras spot the other rover's AprilTag, and the laptop works out where one map sits inside the other.
  3. The laptop merges both maps into one team map.
  4. Places and tasks sync between the rovers, so each holds the same copy without a coordinator.
  5. Planned: the mission planner adds tasks to that shared list.

From laser to map

Two estimates of where the rover is run at the same time, and SLAM ties them to the lidar.

  1. The ESP32 counts encoder ticks (1,540 per wheel turn) and reads the gyro, then sends text lines over USB: ticks 50 times a second, gyro 100 times.
  2. The serial bridge turns ticks into odometry. Both wheels on one side should travel the same distance, so it keeps the smaller count and treats the rest as slip. It re-estimates gyro bias only while the rover stands still.
  3. The EKF blends wheel speed with the gyro's turn rate 30 times a second.
  4. slam_toolbox matches each filtered scan to the map, adds it to a pose graph, and closes a loop when it recognises a place. Its map and corrected pose go to the explorer, the decision layer and the laptop.

How one rover decides

A language model sits in the middle of the decision path, with plain code before and after it. Code handles anything that has one right answer, and the model only proposes.

  1. Reflexes look at the rover's state alone. A flat battery or an e-stop has one correct response, so the model is never asked.
  2. Rules that aren't urgent become advisories: facts written into the prompt for the model to weigh.
  3. The model proposes actions. Its output is forced into a JSON schema whose id fields list only things that exist, so it can't invent a waypoint.
  4. The checker judges each proposal. Refusals are remembered, and anything refused twice is named in the next prompt so the model stops repeating it.
  5. The veto takes a last look against live state, then the executor drives toward the goal and the firmware's own timeouts stop the motors if commands go stale.

How two rovers become a team

Each rover maps on its own. When they meet, AprilTags tell the laptop exactly where one map sits inside the other. Everything here runs in simulation today, with the real team software.

  1. Each rover builds its own map with its own SLAM, starting wherever it happens to be. In the simulation, rover 2's map starts 11.3 m away and turned 180°.
  2. A camera catches the other rover's tag. That one-way sighting is weak, because it reads heading from the tilt of a 10 cm tag.
  3. The rendezvous node stops both rovers. The one that saw the other drives to about 2.4 m away, and the seen rover turns to face it.
  4. With both cameras on each other's tags, the handshake uses only where each tag's centre is, so heading comes from two 2.4 m lines. It publishes where rover 2's map sits inside rover 1's.
  5. The map merger redraws both maps in one frame, once a second, as /team/map.
  6. Places and tasks sync between the rovers' team memories as a CRDT. This step is tested in software and isn't running live yet.

Simulation result, 8 October

Where the rovers met, the join was off by 5 cm. At rover 2's map origin, 4.95 m away, it was off by 10 cm and 0.7°. One-way sightings were about six times worse (51 cm and 4.1°). The merged map covered 139 m², against 106 m² and 100 m² for each rover alone.

When the Wi-Fi drops

Coordinating takes far less data than mapping. A checkpoint is 15 bytes, and one lidar scan is about 1.5 kB. So the plan is to keep coordinating over a slower radio when Wi-Fi fails.

If a teammate goes quiet

After 10 seconds of silence, each rover assumes the network has split and takes only unclaimed tasks inside its own territory, a Voronoi cell around its home position. Silence never hands work over, because a dead link and a dead robot look the same. In software tests this gave no double-assigned tasks in 1,800 random splits, against 69 in 600 when rovers took over a quiet teammate's work after a timeout.

Every feature

Every part of the project, grouped by what it does. Filter by status to see what's on the real rover, what runs in simulation, what's tested software, and what's planned.

Body and firmware

  • Four gear motors with quadrature encoders, 1,540 ticks per wheel turn
  • ESP32 firmware: a PID speed loop per wheel at 50 Hz
  • Motors stop if no command arrives for 500 ms
  • MPU-6050 gyro with a median-of-5 filter
  • Plain-text serial protocol at 115200 baud
  • Battery monitor (blocks autonomy until fitted)
  • Channel B on the front-right encoder
  • Physical e-stop button
  • Robotic arm
  • LoRa radio
  • Inductive charging pads

Knowing where it is

  • Scan filter removes the rover's own deck beams
  • Slip rejection: keep the smaller count on each side
  • Gyro bias re-estimated only when standing still
  • EKF (robot_localization) blending wheels and gyro at 30 Hz
  • slam_toolbox 2D SLAM with loop closure
  • Track width calibrated from laser-only rotation: 0.42 m
  • Scan-matching odometry as a third EKF input
  • Detect lost localization and stop to relocalize
  • Fix velocity spikes from the serial bridge (found in simulation)
  • Fix scans dropped while turning on the spot (found in simulation)

Moving

  • Frontier exploration
  • A* planner on an inflated map
  • Executor: turn, then drive (dry-run by default)
  • Command mux: team commands outrank the explorer
  • Progress monitor: stalled, slipping, timed out
  • Recovery ladder: replan, rescan, back up, abandon, ask
  • Nav2 for point-to-point driving
  • Lane reservations in narrow rows

Deciding

  • Reflexes act before the model
  • Local 3B model with schema-constrained JSON
  • Checker: accept, ask a human, or reject
  • Reflex veto on the chosen action
  • Memory of refused proposals
  • Goal arbitration with a battery round-trip check
  • Mission planner: request to task graph
  • Lessons from logs, shared between rovers
  • Benchmark the model on the Orange Pi

Shared places

  • Checkpoints anchored to pose-graph vertices, so they move with loop closures
  • Created by rules: junctions, frontiers, uncertainty, corners
  • Replicated between rovers as a CRDT
  • Duplicates merged with covariance intersection
  • 15-byte checkpoint packet
  • Checkpoint node running on the robot (M3)
  • Geometry fingerprint check after loop closures

Team

  • Two rovers on one network, with separate topics and frames
  • AprilTag cube on each rover, read by apriltag_ros
  • Rendezvous: stop, approach, face each other
  • Handshake joins the maps (5 cm at the meeting point)
  • Map merger publishes /team/map
  • Deterministic task auction
  • Territory split when the link drops
  • Summon a rover to a checkpoint (M4)
  • Capabilities in the auction: arm, camera, reach

Communication

  • ROS 2 over Wi-Fi between rover and laptop
  • Decision layer reads a link-quality tier
  • Zenoh bridge (DDS discovery is unreliable over Wi-Fi)
  • Clock sync with chrony
  • LoRa fallback for checkpoints
  • Priority lanes: small safety messages first
  • Authenticated messages (SROS2)

Perception

  • Two-stage check: change detector, then vision model
  • Inventory plus allowlist instead of asking the model to judge
  • Detections placed on the map from camera bearing and lidar range
  • Anomaly database that merges repeat sightings
  • Bounding-box object detector
  • Measure where the vision model should run (E5)

Testing and tools

  • Gazebo simulator running the real software, with a virtual ESP32
  • 2,148 test assertions in 15 suites
  • Metrics: ATE, RPE, bootstrap confidence intervals
  • Trajectory recorder and run evaluator
  • RViz2 and a web map view on the laptop
  • Experiments E1 to E8 on the real rovers
  • A second test site, such as a hallway or storage room
  • One-command experiment runner
