Planned Swarm Architecture

Where the project is heading: any number of rovers with different hardware, one shared memory, and tasks that pass between rovers until they're done. Most of this is planned, and the marks show which parts already exist. What runs today is on the Rover Swarm System Map, and both are combined in the zoomable Rover Swarm Explorer.

  • A model proposes, code decidesNo language model drives a wheel or makes a safety call.
  • Silence never hands over workA quiet rover might be broken or just out of range, so its tasks wait for a person.

The finished system

Read it top to bottom. Your request becomes approved tasks in a shared store, every rover holds its own copy of that store, and the rovers do the work in the real world. Bulky data such as maps and camera frames takes a separate path on the right.

On a phone, scroll the diagrams sideways.

How rovers talk to each other

Rovers coordinate mostly by sharing state: places, tasks and claims in the shared store. A handful of fixed messages covers the rest. When Wi-Fi fails, the important part still fits on a slow radio.

The messages

MessageWhat it carriesLaneStatus
CheckpointA place in the shared map: position, kind, what happened, which rover, when, and how wide to searchCoordination; also fits LoRa at 15 bytesSoftware
Request helpA summon: “come here, I need an arm.” It's a high-value assist task, so it can travel as a checkpointCoordination; also LoRaPlanned (M4)
AnnounceA new task: what kind, where, and what it needsCoordinationPlanned
BidWhat the task would cost this roverCoordinationPlanned
AwardWho gets the task. Every rover can also work this out itself from the shared storeCoordinationAuction built; message planned
Release“I'm giving this task back,” after recovery failsCoordinationLogic built; message planned
ReportDone, failed, or what was foundCoordinationPlanned
Lane or dock claim“I'm using this lane segment” or “this dock.” No claim, no entryCoordinationPlanned
LessonWhat happened, with the log entries behind it. Other rovers treat it as untrustedCoordination, low priorityPlanned
Own map + tag sightingsEach rover's map and what its camera saw, for joining mapsMaps + scansSimulation
Camera frameOne image for the vision modelImages, on requestSoftware

Announce, bid, award and report come from the Contract Net Protocol (Smith, 1980). Only the checkpoint has a fixed size so far.

How a task gets finished

Every task in the shared list is in one of these states. The rules about who may move a task, and when, are what stop two rovers from doing the same job.

When things go wrong

Every failure the plan anticipates has a defined response that loses capability, not safety. Most of the responses already exist in software.
